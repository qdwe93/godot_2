## 한 줄 요약

**한 판의 루프가 완성됐고, M12b에서 밸런스가 목표에 도달했다.**
최선 빌드 기준 생존 **572~900초 (평균 13분 28초)**, PRD 목표 10~15분 안이다.

시간보다 중요한 변화는 이것이다 — **조작과 선택이 결과를 가른다.**
M12a에서는 무입력 68.7초 대 최선 빌드 100.5초로 차이가 1.5배뿐이었다. 지금은
무입력 95초 대 최선 빌드 900초로 **9.4배**다. 업그레이드도 25개 중 4~6개만 찍던 것이
39개 중 24~39개까지 간다.

| | M12a | M12b |
|---|---:|---:|
| 무입력 | 68.7초 | **95초** |
| 봇 · 무작위 선택 | 71~96초 | **516초** |
| 봇 · 최선 빌드 | 79~101초 | **572~900초** |
| 도달 레벨 | 5~7 | **24~42** |
| 최종 화력 | 27~32 dps | **207~710 dps** |

근거와 시행착오는 [devlog 018](devlog/018-m12b-power-and-curve.md).

> ⚠️ **밸런스 수치를 만지기 전에 devlog 018을 읽어라.** 특히 ① 곡선은
> `tools/balance_sim.py`로 생성하고 손으로 적지 않는다 ② `enemies_per_spawn`은 1로
> 고정한다 ③ **시뮬레이터로 절대 시간을 예측하지 않는다** (실측과 1.8배 어긋났다).

## 이전 계획 (M9, 완료됨)

**목표**: 같은 게임을 "쳤다는 느낌"이 나게 만든다. 로직은 건드리지 않는다.

1. **타격 피드백** — 적이 맞으면 잠깐 흰색으로 번쩍(0.05초), 죽을 때 작은 파티클이나 확대·페이드
   - `modulate`를 잠깐 바꿨다 되돌리는 것으로 충분하다. `Tween`을 쓰면 코드가 짧다
2. **화면 흔들림** — 플레이어가 피격당했을 때 짧게. 과하면 멀미가 나므로 0.1~0.2초, 진폭 4~6px 수준
   - 카메라가 없으므로 `Main`의 `position`을 흔들거나, 이번 기회에 `Camera2D`를 넣는다. 카메라를 넣으면 **화면 경계 계산(D-007)이 전부 바뀌므로** 넣지 않는 쪽을 권장
3. **경험치 바 가시성 개선** (M8 부채) — 배경/전경 색 대비를 주기
4. **사운드** — 발사, 피격, 레벨업, 사망. 무료 CC0 효과음(예: Kenney Audio)을 받아 쓸 것. **출처와 라이선스를 devlog에 기록**
5. **아트 교체 검토** — 무료 2D 스프라이트를 쓸지, 도형을 유지할지 판단. 도형이라도 색·크기 대비만 정리하면 충분히 읽힌다
6. 테스트 — 시각 효과는 자동 검증이 어렵다. **로직 회귀가 없는지(기존 74케이스 통과)와 캡처 비교로 확인**하고, 이펙트 자체는 "일정 시간 뒤 원래 상태로 돌아오는가" 정도만 테스트

**M9 수용 기준(DoD)**: 전체 스위트 통과 + 전/후 캡처 비교 + 에셋 라이선스 기록

**주의**: M9는 게임플레이 로직을 바꾸지 않는다. 밸런스 수치 조정은 M10이다.

## 작업 규칙 (사고 후 추가)

- **스크립트를 고쳤으면 `--check-only` 문법 검사를 먼저 돌린다.** Godot 4.7은 Variant 추론(`var x := <Variant>`)을 **에러**로 취급해 스크립트 전체가 로드되지 않는다. 게임은 조용히 빈 노드로 실행된다
- **고장 주입 실험 전에 반드시 커밋한다.** 미커밋 상태에서 `git checkout -- <파일>`을 쓰면 마지막 커밋으로 돌아가 작업이 사라진다 (M4에서 실제로 발생)
- 테스트를 수정했으면 **일부러 고장을 내서 FAIL하는지 확인**한다. 통과 확인만으로는 절반이다
