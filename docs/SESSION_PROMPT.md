## 절대 잊으면 안 되는 것 (전부 실제로 당한 것들)

### codex 관련

- **codex는 이 PC에서 파일을 읽지 못한다.** 셸 프로세스 생성이 막혀 있고(`CreateProcessAsUserW failed: 5`) 파일 읽기도 셸에 의존한다
  - 새 파일 생성 → 명세만 적어 위임
  - **기존 파일 수정 → 파일 전문을 작업지시서에 붙여넣어 위임**
  - 한두 줄 자명한 수정 → Claude가 직접
- 작업지시서에 매번 넣을 문구: `Do NOT run git and do NOT run Godot. Shell process spawning is broken here, so you cannot read files.`

### Godot 함정 (전부 에러 없이 조용히 잘못 도는 유형)

- **`:=`를 Variant 값에 쓰면 파싱 에러**로 스크립트 전체가 로드되지 않는다. `get()`, `get_setting()`, 딕셔너리 접근에는 명시적 타입을 쓴다
- **`process_mode` 값**: `INHERIT=0, PAUSABLE=1, WHEN_PAUSED=2, ALWAYS=3, DISABLED=4`. 기억으로 쓰지 말고 확신 없으면 `print(Node.PROCESS_MODE_ALWAYS)`로 확인
- **`.tscn`에서 `script = ExtResource(...)`는 스크립트가 선언한 속성보다 먼저** 와야 한다. 순서가 뒤집히면 그 값은 조용히 버려진다
- **`.tscn` 섹션 순서**: `[gd_scene]` → 모든 `[ext_resource]` → 모든 `[sub_resource]` → 모든 `[node]`. `load_steps` = ext+sub+1
- **물리 스텝 중(`body_entered` 등)에는 충돌 도형 노드를 추가하거나 `monitoring`을 직접 바꾸지 않는다.** `call_deferred`/`set_deferred`를 쓴다. `queue_free()`는 안전
- **GDScript 람다는 지역 변수를 값으로 캡처한다.** 시그널 카운터는 멤버 변수나 Array에 담을 것
- **일시정지 중에는 `physics_frame`이 발생하지 않는다.** 진단·테스트는 `process_frame`으로 기다린다
- 시그널 연결은 **객체를 만드는 쪽에서 그 자리에서** 한다. `get_tree().node_added` 전역 훅 금지

### 검증 규칙

- 스크립트를 고쳤으면 **`--check-only` 문법 검사부터** 돌린다
- 테스트 실행에 **`--quit-after 3600` 필수.** 테스트 스크립트가 파싱 실패하면 `quit()`이 안 불려 무한 대기한다
- 게임 실행·캡처·측정에는 **`--auto-play` 필수.** 타이틀과 레벨업에서 멈춘다
- **유닛 테스트 전부 통과 ≠ 게임 정상.** 마일스톤마다 창 모드 캡처로 눈 검증을 병행한다
- **테스트가 실패하면 구현보다 측정 방법을 먼저 의심한다.** 이 프로젝트에서 실패 원인이 네 번 연속 측정 쪽이었다 (캡처 도구의 프레임/시간 혼동, 람다 값 캡처, 테스트 격리 실패, 무적 시간 잔존)
- **고장 주입 실험 전에 반드시 커밋한다.** 미커밋 상태에서 `git checkout -- <파일>`을 쓰면 작업이 사라진다 (실제로 겪음)
- 하네스 규칙: 케이스 수 검증, `passed=0`은 PASS 아님, 0 대 0 비교 금지, `TEST_ERROR setup_failed`로 조기 중단

### 밸런싱 관련

- **밸런스 테스트가 밸런스 수치를 하드코딩하면 안 된다.** 값이 아니라 불변식(단조 증가/감소, 경계 동작)을 검사할 것. 지금 `tests/test_waves.gd`가 이 문제를 안고 있다
- 진단 출력은 파이프라인으로 받으면 버퍼링되어 진행이 안 보인다. **파일로 직접 리다이렉트**할 것

## 작업 방식

마일스톤은 **한 번에 하나씩**, `구현 → 검증 → 커밋+푸시 → 문서 갱신` 사이클을 완결한다. 범위가 크면 둘로 쪼갠다 (M5~M8에서 전부 그렇게 했다).

문서는 전부 한글 마크다운, 파일명은 영문. 시행착오는 **실패한 시도까지** `docs/devlog/`에 남긴다. 기술 결정은 선택지·결정·근거 형식으로 `docs/DECISIONS.md`에.

**작업이 끝나면 `docs/STATUS.md`를 반드시 갱신한다.** 이 파일 하나로 다음 세션이 이어받는다.
