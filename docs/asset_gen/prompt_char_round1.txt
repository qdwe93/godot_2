# 작업: 캐릭터형 스프라이트 5종 생성 (player / enemy_basic / enemy_fast / enemy_tank / enemy_boss)

Do NOT run git, Godot, python, npm, or any shell command. Shell process spawning is broken on this
machine and every shell call will fail. You have exactly two jobs:
(1) generate 5 images with your built-in image generation tool,
(2) write ONE manifest file with apply_patch.
**Do not modify any other file in the repository.**

## Context — read this before writing any prompt

This is a top-down 2D survivor game. Up to ~240 enemies fill the screen at once on a near-black
`#141419` background. A previous round of assets produced flat geometric pictograms (circle, square,
triangle, hexagon, octagon). They passed all readability checks but look lifeless. **This round adds
character** — the shapes should read as living things, not road signs.

**The hard part is size.** These sprites are drawn at 17 to 60 pixels in game:

| sprite | drawn at | this means |
|---|---|---|
| enemy_fast | 17px | about 3 distinct features fit, no more |
| enemy_basic | 20px | about 3 distinct features fit |
| player | 24px | 4 features |
| enemy_tank | 28px | 5 features |
| enemy_boss | 60px | real detail is possible here |

So "character" cannot mean fine detail. It means: **a readable silhouette with 2 to 4 bold accent
shapes** (eyes, a jaw, a core, plating). Anything smaller than roughly 8% of the sprite's width will
disappear entirely when scaled down.

## The three rules that override any artistic instinct

These are enforced by an automated checker that downscales each image to its in-game size and
measures it. A previous round failed 6 of 8 images on exactly these points.

**Rule 1 — The outer silhouette is fixed and must not change.**
Players with red-green colour blindness cannot tell these enemies apart by colour, so the shape is
the only thing distinguishing them. Add character *inside* and *around* the required silhouette,
never by replacing it.

| sprite | required outer silhouette |
|---|---|
| player | CIRCLE |
| enemy_basic | SQUARE (four sharp 90 degree corners) |
| enemy_fast | TRIANGLE pointing up |
| enemy_tank | HEXAGON (six equal straight edges) |
| enemy_boss | OCTAGON (eight equal straight edges) |

Small protrusions that read as limbs, horns or fins are allowed **only if the underlying shape is
still obvious at a glance**. If a viewer could mistake the hexagon for an octagon, it has failed.

**Rule 2 — No black, no dark grey, no dark outlines. Anywhere.**
This is the rule that killed the previous round. Dark detail looks great at 1024px, but when the
image is averaged down to 20px those dark pixels drag the whole sprite toward black and it vanishes
against the near-black background. The tank came out at 1.73:1 contrast, which is effectively
invisible.

Every accent must be a **LIGHTER tint of the base colour**, or white. Eyes, mouths, seams, plating
lines — all lighter, never darker. If you want an eye to read, make it near-white, not black.

**Rule 3 — Fill the canvas and stay saturated.**
The shape's bounding box must span at least 85% of the canvas width and height. At least 70% of the
shape's area must be the specified base colour at full strength. Do not draw a small creature
floating in empty space, and do not wash the colour out with gradients.

Also: flat colour only. No shading, no gradients, no gloss, no bevel, no drop shadow, no glow, no
blur, no background scenery, no text, no numbers, no watermark. Fully transparent background.

## Rules while generating

- **One generation call per sprite.** Never batch several sprites into one image.
- After each image, check it against these three questions before moving on:
  1. **Is the required silhouette still obvious?** (circle / square / triangle / hexagon / octagon)
  2. **Is there any black or dark grey anywhere?** If yes, regenerate — it will vanish at 20px.
  3. **Does the shape nearly touch the canvas edges?** If it floats in empty space, regenerate.
- Maximum 3 attempts per sprite. If it still fails after 3, record that honestly and stop.
- Record every attempt including failures and exactly what you changed between them.
