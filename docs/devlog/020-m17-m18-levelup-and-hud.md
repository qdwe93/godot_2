## 1. M17 — 레벨업 화면을 카드로

### 1-1. 별 등급이 미처리 항목 하나를 같이 해결했다

백로그에 "레벨업 버튼에 현재 레벨 표시 (`get_level()`은 이미 있는데 UI가 안 씀)"이
있었다. 레퍼런스는 이걸 **별 등급**으로 풀어 놨다. 별 개수가 그 스킬의 `max_level`,
채워진 별이 현재 레벨이다.

한 가지를 정해야 했다 — **채워진 별은 지금 레벨인가, 찍고 난 뒤 레벨인가.**
후자를 골랐다. 카드는 "이걸 고르면 어떻게 되는가"를 보여주는 화면이기 때문이다.
레벨 0짜리 미획득 스킬의 카드에 별이 하나도 안 차 있으면 아무 정보가 없다.

### 1-2. 목록은 정의에서 만든다

슬롯 바와 별을 씬에 하드코딩하지 않았다. `UpgradeData` 의 정의 순서대로 코드에서
만든다. 이 프로젝트는 목록을 하드코딩해서 **튜닝과 콘텐츠 추가를 두 번 막은** 전력이
있다 (`test_waves` 의 밸런스 수치, `test_upgrade_limits` 의 업그레이드 id).

같은 이유로 이름과 설명도 `label`("이름 - 설명") 한 곳에서 갈라 쓴다. 두 벌로
저장하면 언젠가 갈라진다.

### 1-3. 카드가 반투명했다

버튼의 기본 스타일박스가 반투명이라 **카드 한가운데로 주인공이 비쳐 보였다.**
주인공이 화면 정중앙에 고정돼 있으니 하필 가운데 카드에 정확히 겹친다.

테스트는 전부 통과했다. **캡처를 안 봤으면 못 찾았다.**

## 2. M18 — HUD 소품 넷

### 2-1. 배치

```
[일시정지]           0:40              처치 22
[Lv.5] [============ 경험치 바 =====================]
```

체력은 상단 바에서 **주인공 발밑**으로 내려갔다. 레퍼런스와 같은 배치다.
HUD 좌상단의 체력바와 "100/100" 숫자는 지웠다 — 발밑으로 옮긴 뒤로는 같은 정보의
중복이고, 720 단위밖에 안 되는 세로 공간을 두 번 먹는다.

`hud.gd` 는 여전히 체력을 추적한다. 위험 비네트와 사망 요약 화면이 그 값을 쓴다.

### 2-2. 피해 숫자에는 상한이 필요하다

레퍼런스에는 피해 숫자가 그냥 뜬다. 우리는 사정이 다르다 — **적이 219마리까지 나오고
산탄이 7발까지 는다.** 상한이 없으면 초당 수백 개의 `Label` 이 생겼다 사라진다.

`EffectSpawner.MAX_ACTIVE_DAMAGE_NUMBERS = 40` 을 두고, 넘치면 **그냥 안 만든다.**
어차피 사람 눈으로 못 읽는 개수다.

세는 방법도 중요하다. `get_tree().get_nodes_in_group()` 로 매번 세면 초당 수백 번
배열을 할당하게 된다. 정수 카운터를 들고 생성 시 +1, `tree_exited` 에 -1 한다.

**실측 결과 fps 영향 없음** — 적 219마리에서 145fps. M16 측정치(232마리 145fps)와 같다.

### 2-3. 일시정지 상태는 한 노드만 갖는다

일시정지 버튼을 HUD 가 아니라 `GameFlow` 에 뒀다. `get_tree().paused` 를 이미
GameFlow 가 소유하고 있기 때문이다 — 타이틀도, 게임오버도, 재시작도 전부 여기서
건다. 같은 상태를 두 노드가 나눠 가지면 반드시 어긋난다.

그래서 `can_pause()` 가 타이틀·게임오버·**레벨업 중**을 전부 거부한다. 레벨업 3택은
자기 이유로 이미 일시정지를 걸고 있어서, 그 위에서 일시정지 버튼이 또 눌리면
선택하는 순간 게임이 멈춘 채로 남는다.

## 3. 이번에 새로 배운 함정 셋

### 3-1. 자식의 `_ready()` 가 부모보다 **먼저** 돈다

발밑 체력바가 **체력이 가득인데 텅 빈 채로** 보였다.

```gdscript
# 체력바의 _ready()
var current_health: float = float(_player.get(&"health"))   # 0.0 이다
```

`player.gd` 의 `_ready()` 에서 `health = max_health` 를 하는데, 자식인 체력바의
`_ready()` 가 **그보다 먼저** 돈다. 그래서 0.0 을 읽는다.

여기서 끝이 아니다. 그 뒤로도 안 고쳐진다 — 체력이 가득이면 `health_changed` 가
발생할 일이 없기 때문이다 (재생도 만렙에서는 신호를 안 쏜다). 첫 피해를 입을 때까지
빈 바가 계속 보인다. **에러는 하나도 안 난다.**

`call_deferred` 로 미루면 트리 전체가 준비된 뒤에 읽는다.

> 회귀 테스트를 짤 때 주의할 점이 하나 더 있다. **피해를 준 뒤를 보는 케이스로는
> 못 잡는다.** 피해가 신호를 쏘면서 값이 고쳐지기 때문이다. 아무것도 하지 않은
> 상태를 따로 봐야 한다.

### 3-2. 해제된 Object 참조는 `== null` 이 참이다

피해 숫자가 수명이 다해 사라지는지 보는 테스트가 계속 실패했다. 구현은 멀쩡했다.

```gdscript
var created: Node = spawner.spawn_damage_number(...)   # 정상 생성됨
await ...                                              # 수명(0.7초) 경과, 자가 해제
var ok: bool = created != null and ...                 # <- 여기서 false 가 된다
```

Godot 에서 해제된 Object 참조는 `null` 과 같다고 비교된다. 그래서 수명이 끝난 뒤에
`created != null` 을 물으면 **"애초에 안 만들어졌다"와 "만들어졌다가 사라졌다"를
구별할 수 없다.** 생성 여부는 기다리기 **전에** `bool` 로 붙잡아야 한다.

### 3-3. 캐스팅 실패는 조용히 `null` 이 된다

```gdscript
var level_up_ui: Control = _main.get_node("LevelUpUI") as Control   # null
```

`LevelUpUI` 는 `Control` 이 아니라 **`CanvasLayer`** 다. `as` 는 실패하면 예외가
아니라 `null` 을 준다. 그 다음 줄에 가서야 "null 값에 메서드 호출"로 터진다.

## 4. 유닛 통과 != 배선 연결 (또 한 번)

`test_hud_props` 9번 케이스는 `spawn_damage_number()` 를 **직접 불러서** 검사한다.
그런데 `projectile.gd` 에서 그 호출을 지워도 9번은 통과한다.

이 프로젝트에서 "정의는 있는데 게임에서 실행되지 않는" 버그가 이미 세 번 나왔다
(산탄·궤도구 미노출, `spawn_hit()` 호출처 0건, 보스 드랍 메서드 이름 불일치).
전부 유닛 테스트를 통과했었다.

그래서 12번 케이스를 따로 만들었다 — **실제 투사체를 적에 맞혀서** 숫자가 하나 늘고
그 숫자가 투사체의 피해량과 같은지 본다. 고장 주입으로 확인했다: `projectile.gd` 의
호출을 지우면 9번은 통과하고 **12번만 FAIL 한다.**

## 9. 덧붙임 — M18b: 실기에서 나온 지적 3건

빌드를 폰에서 확인한 뒤 사용자가 세 가지를 지적했다. **셋 다 141케이스가 전부
통과하는 상태에서 나왔다.**

### 9-1. 그리는 순서를 아무도 정하지 않고 있었다

몹이 경험치 구슬 **뒤로** 지나갔다. 월드 컨테이너의 `z_index` 가 전부 0 이라
그리는 순서가 곧 **씬 트리 순서**였고, `main.tscn` 에서 `PickupContainer` 가
`EnemyContainer` 보다 나중에 나온다는 이유만으로 젬이 적 위에 그려졌다.

의도한 적이 없는 순서였다. 씬에 노드를 하나 추가하면 조용히 바뀌었을 것이다.

```
바닥(-100) < 젬(-10) < 적(0) < 주인공(10) < 투사체(20) < 이펙트(30)
```

### 9-2. `CanvasLayer.layer` 기본값은 0 이 아니라 **1** 이다

상단 한가운데로 커진 시계가 레벨업 화면의 "스킬 선택" 제목을 **정확히** 덮었다.

HUD 도 레벨업도 `layer` 를 안 적었으니 둘 다 기본값이고, 값이 같으면 다시 씬 트리
순서로 떨어진다. `main.tscn` 에서 `LevelUpUI` 가 `HUD` 보다 먼저 나오므로 HUD 가
위에 그려졌다. 하필 M18 에서 시계를 상단 한가운데로 옮기면서 제목과 좌표가 겹쳤다 —
**M18 이 만든 버그가 아니라, M18 이 드러낸 버그다.**

덮개도 같이 고쳐야 했다. `layer` 를 올려 레벨업이 위로 온 뒤에도 덮개가 반투명
(0.78)이라 HUD 가 그대로 비쳤다. **0.985 까지 올려도** 큰 흰 글자에 굵은 외곽선이라
유령이 읽혔다. 카드 3장이 세로를 다 써서 제목과 시계를 떼어 놓을 자리가 없으므로
완전 불투명으로 갔다 — 레퍼런스의 레벨업 화면도 게임을 비추지 않는다.

### 9-3. HUD 는 CanvasLayer 라 **무엇을 해도** 세계 위에 그려진다

몹이 경험치 바 뒤로도 지나갔다. 이건 z_index 로 못 고친다. 방법은 하나뿐이다 —
**띠를 화면 가장자리로 밀어내는 것.** 경험치 바를 y=122 에서 y=6 으로 올리고 얇게
만들었다. M18 에서 바를 화면 가로 전체로 늘리면서 놀이 영역 한복판을 지르게 된 것이
원인이었다.

### 9-4. 시계가 일시정지 중에도 흘렀다

`hud.gd` 는 `process_mode = 3`(ALWAYS)이라 일시정지 중에도 `_process` 가 돈다.
난이도를 정하는 `EnemySpawner` 의 시계는 멈추므로, 레벨업·일시정지·게임오버마다
둘이 벌어진다. 화면에 보이는 생존 시간이 실제보다 길어진다.

리뷰 백로그에 **A-engineer #8 로 이미 적혀 있던 항목**이다 (M11a, 2026-08-13).
사용자가 실기에서 같은 것을 짚었다.

`ALWAYS` 자체를 끄면 안 된다 — 일시정지 중에도 체력·레벨 표시는 갱신돼야 한다.
멈춰야 하는 것은 시계뿐이다.

> 테스트를 짤 때 주의: **멈추는 것만 보면 부족하다.** `process_mode` 를 통째로 꺼도
> 통과한다. 다시 흐르는 것까지 봐야 한다.

### 9-5. 배운 것

세 문제의 공통점이 있다. **아무도 명시하지 않은 기본값에 기대고 있었다** —
`z_index` 0, `layer` 기본값, "시계는 그냥 흐른다". 전부 에러가 안 나고, 전부
테스트를 통과하고, 전부 눈으로만 보인다.

그래서 새로 붙인 케이스 셋은 **숫자가 아니라 순서**를 검사한다. 값은 얼마든 조정할
수 있어야 하고, 무너지면 안 되는 것은 관계다.

고장 주입 4건 전부 FAIL 확인. 전체 23스위트 **144케이스** 통과.
