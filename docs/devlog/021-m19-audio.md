**날짜**: 2026-08-14
**한 줄**: 게임에서 유일하게 비어 있던 감각을 채웠다. 배경음악은 사용자가 준 곡을,

## 1. 왜 효과음을 받아 오지 않고 만들었나

계획에는 "무료 CC0 효과음(예: Kenney Audio)을 받아 쓸 것, **출처와 라이선스를
devlog에 기록**"이라고 적혀 있었다. 그렇게 하지 않았다. 이유는 세 가지다.

1. **라이선스가 계속 따라다닌다.** CC0 라도 어느 팩의 몇 번 파일인지 기록해야 하고,
   빌드를 배포할 때마다 그 기록이 맞는지 확인해야 한다. 소리 다섯 개를 위해
   질 부담이 아니다.
2. **받은 소리는 길이와 음량이 제각각이다.** 발사음은 초당 10번 넘게 나므로 70ms를
   넘으면 소음이 된다. 받아 온 파일을 그 조건에 맞추려면 결국 잘라내고 음량을
   다시 잡아야 하는데, 이 PC에는 ffmpeg 이 없다.
3. **이 게임의 소리는 단순해도 된다.** 사각파 하나와 노이즈 한 줌이면 되는
   레트로 계열이다. 복잡한 음원이 필요한 자리가 없다.

그래서 `tools/gen_sfx.py` 가 다섯 개를 전부 생성한다. **근거가 코드 안에 있으므로
수치를 고쳐 다시 돌리면 그대로 재현된다.** 라이선스는 우리 것이다.

| 파일 | 길이 | 재료 | 설계 의도 |
|---|---:|---|---|
| `shoot.wav` | 70ms | 사각파 900→320Hz | 초당 10발 넘게 겹친다. **짧고 작을 것** |
| `hit.wav` | 55ms | 노이즈 + 사인 620→380Hz | 발사음보다도 작다 (산탄이면 한 발사에 7번 맞는다) |
| `hurt.wav` | 220ms | 사각파 300→90Hz + 노이즈 | 무적 시간이 있어 자주 안 난다. 낮고 거칠게 |
| `level_up.wav` | 620ms | 4음 상행 (C-E-G-C) + 옥타브 배음 | 화면이 멈추는 유일한 자리. 여기만 '음악'이어도 된다 |
| `death.wav` | 950ms | 사각파 420→55Hz + 사인 배음 | 한 판에 한 번. 마음껏 길어도 된다 |

**음량은 생성 단계에서 맞춰 둔다.** 게임 쪽에서 dB로 다시 깎기 시작하면 "어느 쪽이
진짜 음량인지" 알 수 없어진다 — `gen_sfx.py` 의 peak 값과 `SFX_LIBRARY` 의
`volume_db` 를 둘 다 만지면 다음에 조정할 때 반드시 헤맨다.

## 2. 배경음악

사용자가 준 mp3 (4분 3초, VBR, 5.9MB) 를 `assets/audio/bgm/main_theme.mp3` 로 넣었다.

**반복 재생을 두 곳에서 켠다.** `.import` 의 `loop=true` 와 코드의 `stream.loop = true`
둘 다다. 한쪽만 두면 조용히 4분 만에 멈추는데, 그 증상은 4분을 기다려야 보이고
에러는 하나도 안 난다.

> ⚠️ **웹 빌드가 6MB 커진다.** mp3 는 압축을 더 짜낼 수 없으므로 이건 그냥 비용이다.
> 웹에서 첫 로딩이 눈에 띄게 길어지면 그때 다시 볼 것.

## 3. 구조 — 왜 autoload 인가

`scripts/audio_manager.gd` 는 autoload `Audio` 다. 이유는 **재시작**이다.
`restart()` 는 `reload_current_scene()` 으로 씬을 통째로 갈아 끼우는데, 오디오가
씬 안에 있으면 그때 같이 사라진다.

버스는 세 개다 — `Master` / `Music` / `SFX`. `default_bus_layout.tres` 가 정의하고
`project.godot` 이 **경로를 명시적으로 가리킨다.** 기본 경로와 같은 값이지만 일부러
적었다: 파일이 사라지면 Godot 은 조용히 Master 하나짜리 레이아웃으로 되돌아가고,
그러면 음량 조절이 통째로 죽는데 아무 에러도 안 난다.

Music 버스는 **-8dB** 로 시작한다. 배경음악이 효과음을 덮으면 타격감이 사라진다.

### 일시정지 중에도 살아 있어야 한다

`process_mode = ALWAYS` (3). 두 가지 때문이다.

- 레벨업 3택은 `get_tree().paused` 상태에서 뜬다. **거기서 레벨업 효과음이 나야 한다.**
- 배경음악이 일시정지마다 끊기면 안 된다. 이 게임은 레벨업이 몇 초에 한 번씩 온다.

### 솎아내기 — 초당 수십 번을 그대로 재생할 수는 없다

적이 200마리 넘게 나오고 산탄은 7발까지 늘어난다. 명중음을 그대로 내면 초당 수백
번이다. 그래서 이름별 **최소 간격**을 둔다 (`shoot` 50ms, `hit` 40ms, `hurt` 150ms,
레벨업·사망은 제한 없음). 간격 안에 다시 들어온 요청은 **조용히 버린다** — 에러가
아니라 정상 동작이다.

경과 시간은 `Time.get_ticks_msec()` 로 잰다. `get_process_delta_time()` 누적이나
씬 트리 타이머를 쓰면 **일시정지 중에 멈추고 `Engine.time_scale` 에 끌려간다** —
진단 실행은 `--speed=3` 배속으로 돌리므로 그대로 어긋난다.

재생기는 12개 고정 풀이다. 전부 차 있으면 **가장 오래전에 시작한 것을 빼앗는다.**
요청을 버리지 않는 이유는 하나다 — 사망음이 안 나는 게 제일 나쁘다.

## 4. 어디서 부르는가

시그널 연결은 만드는 쪽에서 그 자리에서 한다는 규약대로, 전역 훅 없이 여섯 군데에서
직접 부른다.

| 소리 | 호출 지점 | 비고 |
|---|---|---|
| `shoot` | `weapon.gd try_fire()`, `shotgun.gd try_fire()` | 산탄은 **펠릿마다가 아니라 한 발사에 한 번** |
| `hit` | `effect_spawner.gd spawn_hit()` | 이펙트와 같은 깔때기. 새 경로를 만들지 않는다 |
| `hurt` | `player.gd take_damage()` | 죽는 프레임에는 내지 않는다 (사망음과 겹쳐 둘 다 뭉개진다) |
| `death` | `player.gd _die()` | |
| `level_up` | `level_up_ui.gd` 의 `visible = true` 바로 그 줄 | 화면이 실제로 뜰 때만 |
| 배경음악 | `game_flow.gd` `start_game()` / `enable_auto_play()` 에서 켜고 `_on_player_died()` 에서 끈다 | 사망음이 들리도록 비운다 |

## 5. 함정 세 개

### 5-1. `project.godot` 의 주석은 `;` 다. `#` 를 쓰면 그 섹션이 통째로 죽는다

autoload 를 등록하면서 설명을 `#` 로 달았다. 결과는 이랬다:

```
SCRIPT ERROR: Parse Error: Identifier "Audio" not declared in the current scope.
   at: GDScript::reload (res://scripts/player.gd:136)
... 여섯 파일에서 같은 오류
```

**`Audio` 를 못 찾는다는 오류만 보면 autoload 를 안 적었나 의심하게 되는데, 적혀
있었다.** `#` 줄이 파싱을 깨뜨려 `[autoload]` 섹션 전체가 무시된 것이다.
`project.godot` 첫 줄부터 `;` 를 쓰고 있는데도 못 봤다.

### 5-2. `create_timer(..., ignore_time_scale = true)` 는 짧은 시간에서 먼저 끝난다

솎아내기가 풀리는지 보려고 `min_interval + 0.02` 초를 기다렸는데 실패했다.
찍어 봤다:

| 요청 | ignore_time_scale=true | 기본 |
|---:|---:|---:|
| 70ms | **53ms** | 76ms |
| 500ms | 492 / 504 / 504ms | 503 / 503 / 504ms |

500ms 에서는 둘 다 정확하다. **짧은 시간에서만 프레임 델타만큼 먼저 끝난다.**
20ms 여유로는 50ms 문턱을 못 넘는다.

고친 방법이 결론이다 — **검사 대상이 쓰는 시계로 기다린다.**

```gdscript
var deadline_msec: int = Time.get_ticks_msec() + int(ceil(min_interval * 1000.0)) + 5
while Time.get_ticks_msec() < deadline_msec:
    await get_tree().process_frame
```

솎아내기가 `Time.get_ticks_msec()` 을 보므로 대기도 같은 시계로 한다. 두 시계를
섞으면 그 차이만큼이 그대로 판정 오차가 된다.

### 5-3. 솎아내기가 있으면 앞 케이스의 잔여 상태가 판정을 가린다

**고장 주입 10건 중 1건을 놓쳤다.** `player.gd` 의 `_die()` 뒤 `return` 을 지워
죽는 프레임에도 피격음이 나게 만들었는데 테스트가 통과했다.

원인: 케이스가 피해 → 사망 순서로 두 번 때리는데, `hurt` 의 최소 간격이 150ms 라
**고장이 없어도 두 번째 피격음은 어차피 솎였다.** 그러니 검사한 것은 "죽는 프레임에
소리를 안 낸다"가 아니라 "솎아내기가 동작한다" 였다.

고치는 방법은 죽이기 직전에 `reset_counters()` 를 한 번 더 부르는 것이다. 그러면
솎아내기가 원인일 가능성이 사라져 남는 건 `return` 하나뿐이다.

> 일반화하면: **억제 장치가 있는 코드를 검사할 때는, 그 억제가 꺼진 상태에서 봐야
> 한다.** 아니면 억제가 결함을 대신 가려 주고 테스트는 초록불을 준다.

# M20 — 음량 설정 (같은 날 이어서)

**한 줄**: 소리를 넣었으니 끌 수 있어야 한다. 일시정지 화면에서 배경음악과 효과음을
따로 조절한다.

## 8. 왜 슬라이더가 아닌가

Godot 기본 테마의 `HSlider` 손잡이는 **16px 짜리 아이콘**이다. 이 게임은 1600×720
폰 화면에서 돌아간다. 손가락으로 그걸 정확히 잡을 수 없다.

−/+ 버튼은 76×76 사각형이라 확실하고, **10% 단위면 음량에는 충분하다.** 이 프로젝트는
터치 대상이 작아서 한 번(M17), 버튼이 반투명이라 또 한 번(M18) 실기에서 데였다.
같은 함정을 세 번 밟을 이유가 없다.

효과음 쪽을 조절하면 **그 자리에서 명중음을 한 번 낸다.** 안 그러면 바뀐 크기를
귀로 확인할 방법이 없다 — 화면을 닫고 적을 만나야 알게 된다.

## 9. 100% 는 "최대"가 아니라 "설계한 믹스"다

Music 버스는 레이아웃에서 **-8dB** 로 시작한다. 배경음악이 효과음을 덮지 않게
정한 값이다. 그런데 `get_music_volume()` 이 버스 dB 를 그대로 역산하면 설정 화면에
기본값이 **40%** 로 보인다. 사용자는 "왜 절반만 켜져 있지?" 하고 100% 로 올릴 테고,
그러면 우리가 정한 믹스가 깨진다.

그래서 `_ready()` 에서 버스 dB 를 `base_db` 로 붙잡고, 사용자가 고른 비율을 거기에
**더한다.**

```gdscript
volume_db = base_db + linear_to_db(linear)   # 100% → base_db 그대로
```

**붙잡는 순서가 중요하다.** 저장된 설정을 적용하기 전에 읽어야 한다. 뒤집으면
지난번에 고른 값이 새 기준이 되어 실행할 때마다 조금씩 조용해진다.

## 10. 캡처가 또 두 개를 잡았다

테스트 19개가 전부 통과한 상태에서 캡처를 찍었더니 두 가지가 보였다.

**① 음량 바가 반투명이라 주인공이 그대로 비쳤다.** Godot 기본 `ProgressBar` 스타일
얘기다. 화면 한가운데 고정된 주인공이 효과음 바 한복판에 그려져 있었다.
M17 레벨업 카드, M18 일시정지 버튼에 이어 **세 번째**다. 일시정지 덮개도 0.82 라
같이 불투명(1.0)으로 올렸다.

**② 화면을 열 때 값을 다시 읽지 않았다.** 음량을 0.4 로 바꿔 두고 일시정지를 열었는데
숫자가 100% 로 남아 있었다. `_ready()` 에서 한 번 읽고 끝이었기 때문이다.
`open_pause_menu()` 에서 `refresh()` 를 부르도록 고쳤다.

> 두 번 다 **테스트는 초록불이었다.** 스타일 알파와 "열 때 갱신"은 아무도 안 보고
> 있었다. 지금은 둘 다 케이스가 있다.

## 11. 고장 주입에서 5건을 놓쳤다 — 그리고 그 이유

처음 돌린 10건 중 **5건이 통과했다.** 하나는 무의미한 고장이었고 넷은 진짜 구멍이었다.

| 놓친 고장 | 왜 못 잡았나 | 어떻게 고쳤나 |
|---|---|---|
| 숫자 라벨 갱신 삭제 | 접근자가 **바**만 읽었다 | 바와 라벨을 따로 내주고 둘 다 검사 |
| 배경음악 저장 삭제 | `save_settings()` 가 두 값을 **함께** 쓴다. 효과음 저장이 배경음악 값까지 같이 남겼다 | 음악과 효과음을 **따로** 저장→재로드 |
| 기준 dB 를 0 으로 | 비교 대상이 `get_music_base_db()` 라 **양쪽이 같이 틀렸다** | `default_bus_layout.tres` 를 직접 읽어 비교 |
| 바를 반투명으로 | 불투명 검사가 **버튼만** 봤다 | `ProgressBar` 의 `background`/`fill` 도 검사 |
| UI 쪽 clamp 삭제 | `AudioManager` 가 또 clamp 한다 — **동작이 안 바뀐다** | 진짜 지점(매니저)을 치고, 범위 밖 요청 케이스를 추가 |

가운데 두 개가 특히 배울 만하다.

> **검사 대상과 기대값이 같은 곳에서 나오면 그 검사는 아무것도 안 한다.**
> `music_db == get_music_base_db()` 는 base 가 무엇이든 항상 참이다. 기대값은
> **정의(레이아웃 파일)** 에서 와야 한다.

> **두 값을 한 번에 바꾸면, 한쪽 경로가 죽어도 다른 쪽이 대신 써 준다.**
> 저장처럼 여러 값을 함께 기록하는 코드는 반드시 **하나씩** 검사해야 한다.
