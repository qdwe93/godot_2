미룬 것 — **밝은 바닥 + 배경 아트**(REFERENCE_UI #8)는 크기가 다르다. 모든 대비
계산의 기준 배경이 통째로 바뀌어 스프라이트 8종 색과
`tools/check_sprite_luminance.py` 의 기준을 전부 다시 잡아야 한다. 한 마일스톤을
통째로 쓴다.

**조이스틱은 떠다니는 방식을 유지하기로 사용자가 결정했다.** REFERENCE_UI #9 는
이제 후보가 아니다.

## 1. codex 가 파일을 읽을 수 있게 됐다 (이슈 12 / D-014 정정)

지금까지의 규약은 이랬다 — "codex 는 이 PC 에서 파일을 읽지 못한다(읽기에도 셸을
쓴다). **기존 파일 수정을 위임할 때는 지시서에 파일 전문을 첨부한다.**"

이번에 확인해 보니 **더는 사실이 아니다.** codex 가 `node_repl/js` MCP 로 파일을
읽는다. 싸게 검증했다 — `scripts/xp_gem.gd` 의 줄 수와 3행 내용을 물었더니
25줄 / `@export var value: float = 1.0` 로 정확히 답했고, 실제 파일과 일치했다.

바뀌는 것: **지시서에 파일 전문을 붙일 필요가 없다.** 이번 M21 지시서 3장은
전부 "이 파일을 읽고 이렇게 고쳐라" 형식이었고 잘 동작했다. 대신 지시서에
**"고치기 전에 반드시 해당 파일을 읽어라"** 를 명시했다.

셸 실행 불가(`CreateProcessAsUserW failed: 5`)는 **그대로다.** 실행·임포트·
테스트·git 은 여전히 전부 Claude 가 한다. 지시서의 셸 금지 문구도 그대로 유지한다.

## 2. 색종이 — 텍스처가 없으면 먼지가 된다

`CPUParticles2D` 를 레벨업 화면(`Dimmer` 다음, `Title` 앞)에 넣었다. 처음에는
텍스처 없이 넣었다. 유닛 테스트는 전부 통과했고 `emitting=true` 도 확인됐다.

**캡처를 보니 화면에 먼지가 낀 것처럼 보였다.**

텍스처가 없으면 파티클은 1x1 흰 사각형이 된다. 각속도를 아무리 줘도
**정사각형은 도는 것이 눈에 안 보인다.** 색종이의 정체는 "얇은 조각이 뒤집히는
것"인데 그게 통째로 없었다.

`tools/make_ui_icons.py` 에 12x20 흰 직사각형을 만드는 `draw_confetti()` 를
추가했다. **흰색으로 그린다** — `color_initial_ramp` 의 색이 곱해지기 때문이다.
여기에 색을 칠하면 두 색이 곱해져 탁해진다.

| | 전 | 후 |
|---|---|---|
| 텍스처 | 없음 (1x1 흰 사각형) | 12x20 흰 둥근 직사각형 |
| `scale_amount` | 3.0 ~ 7.0 | 0.7 ~ 1.3 |
| `amount` | 48 | 64 |
| 보이는 것 | 먼지 | 뒤집히며 떨어지는 색종이 |

**이걸로 "캡처로만 발견한 결함"이 네 번째다** (보스 실루엣, 반투명 레벨업 카드,
반투명 일시정지 메뉴, 그리고 이번 먼지 색종이). 그리기 경로는 자동 검증이 안 된다.

회귀 테스트는 `confetti_is_drawn_and_not_dust` 다. 텍스처가 있는지뿐 아니라
**정사각형이 아닌지**까지 본다.

### 딸려온 것 두 가지

- `emission_rect_extents` 를 `Arena.get_size()` 로 맞춘다. 기준 해상도 1280 을
  그대로 쓰면 S21(1600x720)에서 **오른쪽 320px 에 색종이가 안 떨어진다.**
  M14 이후 계속 나오는 같은 함정이다
- 노드에 `process_mode = 3`(ALWAYS)을 **명시**한다. 레벨업 화면은 일시정지
  상태이므로 이게 없으면 색종이가 얼어붙는다. 부모에서 상속되긴 하지만
  명시해야 테스트가 값을 확인할 수 있다

`CPUParticles2D.EMISSION_SHAPE_RECTANGLE` 은 **3** 이다 (2 가 아니다).
CLAUDE.md 규칙대로 찍어서 확인했다.

## 3. 숫자키 — 가장 중요한 케이스가 실패를 숨기고 있었다

3택은 마우스/터치로만 고를 수 있었다. WASD 로 움직이는 게임인데 레벨업마다
손을 옮겨야 한다 (리뷰 A-designer #5).

`_unhandled_key_input` 으로 1/2/3 을 받고, 화면이 뜨면 첫 카드에 `grab_focus()` 를
건다 (방향키 이동 + Enter). 카드 좌상단에 숫자 배지를 넣었다 — 키가 먹는다는 걸
알려 주지 않으면 기능이 없는 것과 같다.

### 여기서 진짜 문제가 나왔다

`_unhandled_key_input` 은 **가상 함수라 이름을 잘못 적어도 에러가 안 난다.**
그냥 안 불릴 뿐이다. 그래서 훅(`feed_key_event_for_testing`)이 아니라 진짜
경로(`get_viewport().push_input()`)를 태우는 케이스를 따로 뒀다.

그 케이스가 통과했다. 그런데 **고장 주입에서 안 잡혔다.**

```
MISSED   엔진이 핸들러를 안 부름(가상함수 이름 변경)
         TEST_CASE real_input_path_reaches_the_number_keys SKIP headless 실제 입력 경로 미지원
```

테스트에 이런 도피로가 있었다.

```gdscript
if reached:
    _record(..., true, detail)
elif DisplayServer.get_name() == "headless":
    _record_skip(..., "headless 실제 입력 경로 미지원; " + detail)   # <- 여기
else:
    _record(..., false, detail)
```

**배선이 끊기면 FAIL 이 아니라 SKIP 으로 내려앉는다.** 스위트는 초록불을 준다.
가장 중요하다고 따로 만든 케이스가 정확히 그 상황에서만 침묵한다.

도피로를 넣은 것은 나였다 — 지시서에 "헤드리스에서 동작하지 않으면 SKIP 으로
기록할 수 있게" 라고 적었다. 그런데 **측정해 보니 `push_input` 은 헤드리스에서
동작한다.** 도피로가 필요 없었고, 필요 없는 도피로는 결함을 가려 주기만 한다.

지우고 다시 주입하니 잡혔다.

> **모르면 도피로를 만들지 말고 측정해라.** "안 될지도 모르니 SKIP" 은 안전한
> 선택처럼 보이지만, 그 케이스가 존재하는 이유를 정확히 무력화한다.

## 4. 고장 주입 18건 — 놓친 3건이 서로 다른 이유였다

1차로 16건을 주입해 **13건이 잡히고 3건이 안 잡혔다.** 셋의 원인이 전부 달랐다.

| 놓친 것 | 원인 | 처리 |
|---|---|---|
| 핸들러 미등록 | **테스트 결함** (위 3절의 SKIP 도피로) | 도피로 제거 → 재주입에서 CAUGHT |
| 숨은 상태 가드 제거 | **주입이 결함이 아니었다.** `choose()` 안에 같은 가드가 또 있어 동작이 안 바뀐다 | 두 겹 다 뜯으니 CAUGHT |
| 범위 가드 제거 | 두 겹을 다 뜯어도 동작이 같다. 배열 범위 밖 접근이 **런타임 에러로 끝나** 아무 일도 안 일어난다 | 동작이 실제로 달라지는 고장(범위 밖 키를 마지막 카드로 clamp)으로 바꾸니 CAUGHT |

세 번째가 특히 배울 것이 있다. **"가드를 지웠는데 테스트가 안 깨진다"가 곧
"테스트에 이빨이 없다"는 아니다.** 지운 자리가 어차피 에러로 막히면 관측 가능한
동작은 그대로다. 그건 결함이 아니라 그냥 다른 방식의 거절이다. 테스트의 이빨을
보려면 **실제로 잘못된 결과가 나오는 고장**을 넣어야 한다.

최종적으로 18건 주입 전부 잡혔다.

## 5. 무적 깜빡임

피격 후 0.5초 무적인데 화면에 아무 표시가 없었다 (리뷰 A-designer #7).

`Sprite` 의 `self_modulate` 알파를 1.0 과 0.3 사이에서 **계단식**으로 오간다
(0.1초 간격, 0.5초에 5회). `modulate` 가 아니라 `self_modulate` 인 이유는
자식(`Danger` 오버레이)까지 흐려지면 안 되기 때문이다.

**부드러운 sin 맥동을 쓰지 않았다.** 위험 상태(저체력)가 이미 그 문법을 쓰고
있어서 둘이 구별되지 않는다. 저체력이면서 무적인 상황은 자주 일어난다 —
피격 → 저체력 → 무적이 한 번에 온다. `danger_blink_does_not_fight_invincibility`
가 그 상황에서 **둘 다** 변하는지 본다.

복원은 **정확히 1.0** 이어야 한다. `is_equal_approx` 로 검사하면 0.999 로 남는
고장을 놓치고, 주인공이 영원히 아주 살짝 흐리다. 회귀 케이스는 복원을 보기 전에
**먼저 1.0 미만이 됐던 것을 확인한다** — 그게 없으면 "애초에 안 깜빡였다"와
"제대로 복원했다"를 구별할 수 없다.

## 6. 젬 획득음

`tools/gen_sfx.py` 에 `pickup()` 을 추가했다 (50ms, 사인 880→1400Hz + 배음).

| 파일 | 길이 | peak |
|---|---:|---:|
| `pickup.wav` | 50ms | **0.17** (여섯 개 중 가장 작다) |

자석 반경 안에 젬이 수십 개 들어오면 한 프레임에 한꺼번에 불린다. 솎아내기
(`min_interval` 0.07 = 초당 최대 14번)는 **`AudioManager` 안에서** 하고
`xp_gem.gd` 는 그냥 부른다 — M19에서 정한 규약 그대로다.

`SFX_LIBRARY` 에 등록만 하면 기존 `every_sfx_file_is_registered` /
`every_sfx_actually_plays` 가 디스크와 표를 양방향으로 맞춰 보므로 **새 케이스가
필요 없다.** 없는 것은 배선이었다 — `collecting_a_gem_calls_the_sound` 가
실제로 젬을 수집시켜 재생 수를 센다.

주의 하나. 그 케이스는 검사 **직전에** `reset_counters()` 를 부른다. 안 그러면
앞 케이스가 남긴 시각 때문에 이 호출이 솎여서 **고장이 없어도 0 이 나온다.**
M19 에서 배운 "억제 장치가 켜진 채로는 그 아래 결함을 못 본다"의 반복이다.

`pickup_is_the_quietest_and_throttled_sound` 는 수치를 하드코딩하지 않는다.
`min_interval > 0` 이고 `volume_db` 가 **표 전체의 최솟값**인지를 본다.

## 8. 새로 만든 상설 도구

`tests/diag_levelup_capture.tscn` — 레벨업 화면을 띄운 채로 캡처한다.
**`--auto-play` 를 쓰면 안 된다** (GameFlow 가 즉시 자동 선택해 화면이 닫힌다).
그래서 진단 스크립트가 직접 `start_game()` 을 부르고 경험치를 밀어 넣는다.

```powershell
& "C:\Program Files (x86)\Godot\Godot_v4.7.1-stable_win64_console.exe" --path "C:\Workspaces\game_make\test_godot_2" --quit-after 900 "res://tests/diag_levelup_capture.tscn" -- "--capture=<경로>.png" "--capture-after=2.5"
```

레벨업 화면은 이제 캡처로 봐야 할 것이 세 가지다 (카드 불투명 / 시계 안 가림 /
색종이가 먼지가 아님). 매번 새로 쓰지 말고 이걸 쓴다.

게임 진행에 영향을 주는 것이 없다. 45초 창 모드 실행 화면으로 난이도를 판단하지
