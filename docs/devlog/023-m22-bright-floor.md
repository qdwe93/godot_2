# devlog 023 — M22: 밝은 바닥과 배경 아트

**날짜**: 2026-08-15
**직전**: [devlog 022](022-m21-polish.md) (M21 감각 폴리시)

레퍼런스([REFERENCE_UI](../REFERENCE_UI.md) 1-5절)에서 마지막까지 남아 있던 두 항목
중 하나, **밝은 바닥**을 가져왔다. 근검정 위 #1E1E26 격자에서 **밝은 회보라 포석
타일**로 바꿨고, 잃어버린 대비는 **스프라이트에 구운 어두운 외곽선**으로 되찾았다.

---

## 1. 계획의 한 줄이 성립하지 않았다

M21 종료 시점의 계획(STATUS "다음 마일스톤 계획" 1번)은 이렇게 적혀 있었다.

> "밝기 순서"를 **"대비 순서"** 로 바꾼다. (…) 순서 자체
> (주인공 > 보스 > 탱커 > 기본 > 빠른 > 젬 > 투사체)는 그대로 유지한다

**그 둘은 동시에 성립하지 않는다.** 그림을 건드리기 전에 계산해서 알았다.

대비 순서가 휘도 순서와 같은 것은 **배경이 모든 요소보다 어두울 때뿐이다.**
바닥이 가장 어두운 요소(투사체, 휘도 0.150)를 넘어서면 그 요소의 대비가 다시
올라가기 시작하고 순서가 접힌다. 성립 상한은 약 **#6E6989**다.

| 바닥 | 배경 휘도 | 순서 위반 |
|---|---:|---|
| #3A3A4A | 0.044 | 0건 |
| #6A6480 | 0.137 | 0건 |
| #6E6989 ← 상한 | 0.152 | 0건 |
| #726D8E | 0.165 | 1건 |
| **#A9A3C4 (레퍼런스급)** | 0.386 | **5건** |

레퍼런스급 실측은 `보스 1.00 < 탱커 1.29 < 기본 1.51 < 빠른 1.58 < 젬 2.01 <
투사체 2.18` 로 **거의 뒤집힌다.**

외곽선으로는 못 고친다. 균일한 검은 테두리는 모든 요소를 같은 방향으로 밀 뿐이고,
순위별로 두께를 다르게 줘서 순서를 만들려면 **가장 밝은 주인공을 가장 두껍게 검게
묻어야** 한다 — D-019가 지키려던 그림을 정확히 망가뜨린다.

사용자에게 두 후보(중간 밝기로 물러서기 / 레퍼런스급 + 순서 규칙 폐기)를 숫자와
함께 물었고 **레퍼런스급**으로 결정했다. 경위와 대체 규칙은 [D-020](../DECISIONS.md).

> **교훈**: 계획서의 한 줄이 두 조건을 동시에 요구할 때, 그것이 정말 동시에
> 성립하는지는 **그림을 만들기 전에** 산술로 확인할 수 있다. 이번엔 후보 바닥
> 6개에 대해 순서 위반 건수를 세는 20줄짜리 스크립트로 끝났다.

## 2. 판정 기준을 먼저 고쳤다

계획의 순서(도구 → 타일 → 색 → 외곽선 → 측정)를 지켰다. 기준이 옛것인 채로 그림을
고치면 무엇이 맞는지 알 수 없기 때문이다.

`tools/check_sprite_luminance.py` 가 바뀐 곳:

| 예전 | 지금 |
|---|---|
| 배경 = 상수 하나 (`BACKGROUND`) | **타일 PNG에서 직접 읽은 두 톤** (2/98 백분위) |
| 평균 휘도 하나로 판정 | **외곽 대비**(3:1)와 **본체 색차**(CIE76 dE 25)를 양쪽 톤에서 |
| 밝기 순서 7종 | **적 변종끼리 dE 20** |
| 8종 검사 | **5종** — 젬·투사체·궤도구는 `ColorRect`라 PNG가 안 그려진다 |

**단일 출처는 타일 PNG 자체다.** 예전에는 바닥색이 세 곳(`main.tscn`,
`background_grid.gd`, 검사 도구)에 사본으로 있었다. 지금은 도구가 PNG를 읽고,
`background_grid.gd` 는 `read_tile_mean_colour()` 로 언더레이를 PNG에서 유도한다.
`GRID_TINT` 상수는 없앴다.

타일이 없으면 **고정색으로 대체하지 않고 exit 2로 죽는다.** 조용한 대체값이야말로
이 재작성이 막으려던 "틀린 초록불"이다.

## 3. 흰색은 쓸 수 없었다

레퍼런스의 필드 경계선은 **흰색**이다. 그대로 하면 두 가지가 깨진다.

1. 휘도 1.0이 명도 대역을 통째로 벌린다
2. 주인공 본체(축소·외곽선 후 실측 **#74A1B1**)와 CIE76 dE가 **23.3**까지 좁혀져
   밝은 톤 위에서 주인공이 흐려진다

처음 만든 타일의 경계선 `#C3BDDA`가 정확히 이 경우였고 **주인공 1종만 실패**했다.
문턱값을 내리는 대신 **밝기 대신 채도로 경계를 냈다** — `#C0B0E4`. dE 23.3 → 30.8.

계획서의 "화려함은 채도와 무늬로 낸다"가 바로 이 자리였다. 추상적인 조언인 줄
알았는데 실제로 걸렸고, 처방도 그대로 들어맞았다.

## 4. 외곽선은 캔버스를 키우지 않고 굽는다

`tools/sprite_outline.py`. 원본은 `assets/sprites_src/`에 보관하고 결과만
`assets/sprites/`에 쓴다. 다시 돌릴 수 있어야 하기 때문이다(`--revert`).

**캔버스 크기를 바꾸면 안 된다.** 씬이 `scale = Vector2(0.28125, …)`처럼 텍스처
크기에서 계산한 값을 박아 두고 있어서, 캔버스가 커지면 **화면 크기가 조용히
바뀐다.** 게다가 기존 스프라이트는 알파 경계가 캔버스 끝에 닿아 있어(bbox가 x=0과
x=256에 걸린다) 팽창시킬 여백 자체가 없다.

그래서 순서가 이렇다 — **알파 경계로 자르고 → (W-2t)로 줄여서 → 가운데 놓고 →
팽창시킨다.** 표시 크기는 그대로고 실루엣만 테두리를 얻는다.

두께는 표시 크기에 비례한다: `t_display = clamp(0.05 × 표시크기, 2, 5)`.
보스(180px)와 투사체가 같은 두께면 하나는 안 보이고 하나는 뭉갠다.

| 에셋 | 표시 | t_display | 원본 t |
|---|---:|---:|---:|
| player | 72px | 3.60px | 13px |
| enemy_boss | 180px | 5.00px (상한) | 7px |
| enemy_tank | 84px | 4.20px | 13px |
| enemy_basic | 60px | 3.00px | 13px |
| enemy_fast | 51px | 2.55px | 13px |

젬·투사체·궤도구는 `ColorRect`라 이 도구가 닿지 않는다. 씬에서 **Sprite 뒤에
2px 큰 `Outline` ColorRect**를 깔았다. `Outline`이 `Sprite`보다 **뒤에** 오면
칠을 덮어 단색 사각형이 되는데 **에러는 안 난다** — 그래서 순서를 테스트가 본다.

## 6. 캡처가 또 하나를 잡았다

전 스위트 24개 178케이스가 초록불인 상태에서 캡처를 찍었고, **피해 숫자가 거의
안 읽혔다.**

피해 숫자는 흰 글자 + 8px 검은 외곽선이다. 근검정 바닥에서는 흰 글자 자체가 대비를
냈지만 밝은 회보라에서 흰색은 **2.4:1**뿐이라 **외곽선이 혼자 떠받친다.** 그런데
`modulate.a`는 글자와 외곽선을 함께 흐리므로 **사라지는 동안 떠받칠 것이 같이
없어진다.** `FADE_START`가 0.35(수명 0.7)라 **수명의 절반이 흐려지는 구간**이었다.

0.5로 올려 71%를 불투명하게 유지했다.

같은 종류로 **터치 조이스틱**도 미리 뒤집었다. 반투명 **흰색**(알파 0.22)은 밝은
바닥과 섞이면 (0.74, 0.72, 0.81)이 되어 거의 구분되지 않는다. 근검정 반투명으로
바꿨다. **밝은 바닥에서 대비를 내는 방향은 위가 아니라 아래다.**

> 이 프로젝트에서 색·그리기 결함이 캡처로만 발견된 것이 이걸로 **여섯 번째**다
> (보스 실루엣, 반투명 카드, 반투명 메뉴, 먼지 색종이, 피해 숫자, 조이스틱).

## 7. 고장 주입 8건 — 전부 잡았다

기준을 바꾸는 작업이라 "통과했다"가 가장 못 믿을 상태다.

**도구 쪽 4건**

| 주입 | 결과 |
|---|---|
| 외곽선 없는 원본을 넣는다 | 잡음 — 1.78:1 / 1.41:1 로 실패 |
| 타일 파일을 없앤다 | 잡음 — exit 2, 고정색 대체 없음 |
| 명도 대역을 흰 경계선으로 벌린다 | 잡음 — 타일 생성 자체가 막힘 |
| 탱커를 기본과 같은 그림으로 만든다 | 잡음 — 변종 dE 1.7 로 실패 |

**엔진 쪽 4건**

| 주입 | 결과 |
|---|---|
| 젬의 `Outline` 노드를 지운다 | 잡음 (2케이스가 동시에 FAIL) |
| 외곽선을 스프라이트보다 밝게 만든다 | 잡음 |
| 언더레이 동기화를 끊는다 | 잡음 |
| 타일 명도 대역을 벌린다 | 잡음 — `dark=0.3631 bright=1.0000` |

> 마지막 건은 **처음에 "놓침"으로 나왔는데 원인이 테스트가 아니라 주입 하네스의
> 버그였다.** `"_validate_colours()"` 를 치환하려다 함수 **정의 줄**이 먼저 걸려
> 타일이 아예 재생성되지 않았다. 주입이 실제로 들어갔는지부터 확인해야 한다 —
> M21에서 배운 "가드를 지웠는데 안 깨져도 이빨이 없는 건 아니다"의 반대편 사례다.

## 8. 남은 것

- 레퍼런스 잔여는 **코인/메타 성장** 하나뿐이다 (REFERENCE_UI 3절 10번)
- 젬은 아직 **초록 정사각형**이다. 레퍼런스는 다이아몬드다. `xp_gem.png`(마름모)가
  디스크에 있지만 씬은 `ColorRect`를 쓴다 — 바꾸려면 `Sprite2D` 전환이 필요하고
  그건 `color` 주입이 조용히 죽는 종류의 변경이라 따로 다룬다
- `scripts/wave_data.gd` 의 `color` 필드는 M15에서 텍스처로 바뀐 뒤로 **렌더링에
  안 쓰인다.** 지우는 것은 별건이다
- **밸런스는 손대지 않았다.** 동결이 유효하다
